Case files

Four systems I built at Uber, written up the way I’d write up an incident. Internal data stays private; the method doesn’t need it.

Every flag comes with a reason Replaced manual monthly metric reviews with statistically routed, explainable anomaly flags.
Signal
Monthly metric checks relied on people inspecting dashboards and on fixed thresholds, which stop working in a market that keeps growing.
Investigation
A steady series and a trending series need different tests. One rule for both either misses real breaks or cries wolf.
Fix
An Augmented Dickey-Fuller test sorts each series first, then routes it to z-score, median-absolute-deviation or percentage-change rules. Each result is one flag with a plain-English reason.
Impact
Validation is repeatable and auditable, and results publish straight to the people who use them.

Python, pandas, statsmodels, Presto, Google Sheets API

Same-day alerts instead of month-end surprises Data issues now reach the team on the day data lands, not after reports are wrong.
Signal
When ingestion broke, nobody knew until month-end reporting already looked wrong.
Investigation
Breaks showed up as sudden drops in counts against each source’s own history, so a per-source baseline was the right yardstick.
Fix
Anomaly SQL across 15+ ingestion tables compares counts with a 6-month rolling mean and standard deviation, sorts drops by severity, suppresses repeats and posts Slack alerts with trend context and root-cause links.
Impact
Detection moved from month-end to the day of ingestion.

SQL (Presto), pandas, Slack API, Hive

Rebuilding a dashboard estate from Tableau to Flask Heaviest pages load about 65% faster, with data-quality checks and sign-off the old workbook couldn’t support.
Signal
A nine-dashboard Tableau workbook was slow, hard to extend, and had no place for the validation workflow analysts needed.
Investigation
Most of the slowness came from live warehouse queries on every page view, and the business logic was locked inside 55 calculated fields.
Fix
I rebuilt every calculation as a tested pandas metrics layer behind Flask, fed by 13 scheduled Presto extracts with caching. I then added a 14-check data-quality monitor and an 8-state analyst sign-off workflow.
Impact
About 65% faster on the heaviest pages, no live warehouse queries when someone opens a page, and sign-off that used to live in loose spreadsheets.

Flask, pandas, Plotly, Presto, SQLite

Finding which pipeline stage broke the number Counts traced through every stage across 213 warehouse tables, so a break points to one stage.
Signal
When a number moved, nobody could say which stage of the pipeline caused it.
Investigation
Distinct counts should be conserved, or change predictably, from one stage to the next. Wherever that stops being true is where the break is.
Fix
A dashboard follows counts through ingestion, deduplication, matching, classification and fact tables, with stage-to-stage checks and banded thresholds.
Impact
Breaks are localised to a single stage, backed by 27 unit tests.

Flask, pandas, Plotly, custom SVG, Presto, pytest

How I work

The same five steps whether it’s a one-off question or a production system.

  1. Pin down the question

    What decision will this number change, and for whom?

  2. Define the metric

    Write down exactly what counts, what doesn’t, and why, before any SQL.

  3. Build it

    SQL and Python, drafted with AI coding agents from a written spec.

  4. Prove it

    Reconcile against sources, test edge cases, and log every decision.

  5. Watch it

    Ship it with its own checks and alerts, so I hear about problems first.

Where AI fits

I use Cursor and Claude every day to write first drafts of SQL and pandas from a written spec, and to speed up root-cause digging. A spec document, a dated decision log and unit tests decide what actually ships. That’s how one analyst can run about 20,000 lines of production analytics code.
